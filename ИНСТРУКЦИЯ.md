# InvestAdvisor — инструкция пользователя

Полное руководство по установке, настройке и повседневному использованию
InvestAdvisor. Проект находится в статусе **альфа-версии** (`1.0.0-a`): базовая
функциональность работает, но возможны неточности в парсинге отчётов отдельных
брокеров и в расчётах на краевых случаях. Относитесь к результатам как к
рекомендации, а не к торговому приказу.

---

## 1. Что это и зачем

InvestAdvisor собирает ваш портфель (ИИС + внешние брокеры) в одном месте и
считает, **что именно и сколько лотов** докупить при пополнении, чтобы вернуть
портфель к целевым весам. Дополнительно:

- следит за маржинальным долгом и «подушкой» TMON;
- находит момент для выхода из «хвостов» (позиций, которые вы решили закрыть);
- присылает сигналы в Telegram.

Программа **не торгует сама** — она только читает данные и подсказывает.

## 3. Установка и запуск

Требования: **Python 3.12+** (backend), **Docker** (опционально), **Java 17** и
**Gradle** (только для сборки клиента).

### 3.1. Шаг 1 — склонировать проект

```bash
git clone https://github.com/Chistovik92/invest-advisor.git
cd invest-advisor
```

### 3.2. Шаг 2 — создать файл настроек

```bash
cp .env.example .env
```

Откройте `.env` и заполните токены (см. раздел 4).

### 3.3. Шаг 3 — запустить backend

**Вариант A — Docker (проще всего):**

```bash
docker compose up --build
```

**Вариант B — вручную:**

```bash
cd backend
pip install -r requirements.txt --extra-index-url https://opensource.tbank.ru/api/v4/projects/238/packages/pypi/simple --trusted-host opensource.tbank.ru
PYTHONPATH=. uvicorn app.main:app --host 0.0.0.0 --port 8085
```

После запуска:
- API и Swagger-документация: **http://localhost:8085/docs**
- Проверка статуса: `GET http://localhost:8085/api/health`

## 4. Настройка токенов (файл `.env`)

Все переменные необязательны, кроме `TINVEST_TOKEN` — без него основной портфель
не читается.

```ini
# ── Т-Инвестиции (основной брокер) ────────────────────────────
# Создайте токен в настройках Т-Инвестиций: «Только чтение».
# Формат обычно начинается с "t.".
TINVEST_TOKEN=t.ваш_токен_только_для_чтения

# Номера счетов. Оставьте пустыми — сервис найдёт ИИС и TMON автоматически.
IIS_ACCOUNT_ID=
TMON_ACCOUNT_ID=

# ── Брокеры с открытым API ────────────────────────────────────
BCS_REFRESH_TOKEN=
FINAM_TOKEN=
FINAM_CLIENT_ID=
ALOR_REFRESH_TOKEN=
ALOR_PORTFOLIO=

# ── Telegram-бот ──────────────────────────────────────────────
# Токен — от @BotFather. CHAT_ID — ваш личный id (узнать у @userinfobot).
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=

# ── Сервер ────────────────────────────────────────────────────
API_HOST=0.0.0.0
API_PORT=8085
```

После изменения `.env` перезапустите backend.

## 5. Настройка портфеля (`backend/config.yaml`)

Здесь задаются целевые веса. Файл можно править вручную или через API
`GET/POST /api/config`.

### 5.1. Целевые веса классов активов

```yaml
portfolio_targets:
  asset_classes:
    stocks: 0.55            # акции
    bonds_ofz_long: 0.25    # длинные ОФЗ
    bonds_short_float: 0.12 # короткие ОФЗ + флоатеры
    bonds_currency: 0.08    # валютные / замещающие облигации
```

Сумма весов должна равняться 1.0.

### 5.2. Ядро акций

```yaml
  stocks:
    SBER: { target_weight: 0.16, name: "Сбербанк" }
    T:    { target_weight: 0.12, name: "Т-Технологии", freeze_buy: true }
```

- `target_weight` — доля **внутри класса акций** (0.16 → 16 % от акций).
- `freeze_buy: true` — запрет докупать этот инструмент (например, когда позиция
  уже перегружена).

### 5.3. Облигации для докупки

```yaml
  bonds_to_buy:
    - ticker: "SU26236RMFS8"
      name: "ОФЗ 26236"
      group: "bonds_short_float"
      weight: 0.40
```

`group` должен совпадать с одним из ключей `asset_classes`, а `weight` — доля
внутри этой группы.

### 5.4. «Хвосты» на выход

```yaml
  exit_candidates:
    - { ticker: "WUSH", target_pnl_pct: 0.0 }
    - { ticker: "VSEH", target_pnl_pct: 2.0 }
```

Как только PnL позиции достигнет `target_pnl_pct`, сервис пришлёт сигнал в
Telegram, что «хвост» готов к продаже.

## 6. Загрузка данных от брокеров без API

### 6.1. Импорт отчёта (HTML / XLSX / CSV)

1. Скачайте отчёт о позициях у брокера (обычно «Отчёт брокера» → «Позиции»).
2. Загрузите его через API, указав ID брокера из таблицы раздела 2.2.

Через Swagger (`http://localhost:8085/docs`) — endpoint
`POST /api/import-report/{broker_id}`.

Через `curl`:

```bash
curl -X POST "http://localhost:8085/api/import-report/vtb" \
  -F "file=@./vtb_portfolio.xlsx"
```

Поддерживаемые форматы:
- **`.html` / `.htm`** — страница отчёта Сбера / Альфы.
- **`.xlsx`** — Excel-отчёт ВТБ, ГПБ, Альфы, РСХБ, Финуслуг.
- **`.csv`** — универсальный CSV с колонками `ticker`, `quantity`, `price`
  (разделитель `;`). Дополнительно читаются `name`, `type`, `avg_price`.

### 6.2. Синхронизация через QUIK (для Сбера, ВТБ, ПСБ, РСХБ и др.)

1. Откройте `tools/quik_bridge.lua`.
2. В первой строке укажите ID брокера: `local BROKER_ID = "sovcom"`.
3. При необходимости укажите адрес сервера (по умолчанию
   `http://127.0.0.1:8085/api/quik-bridge/`).
4. Запустите скрипт в QUIK: **Сервисы → Lua-скрипты → добавить → запустить**.

Скрипт раз в минуту отправляет позиции из таблицы «Лимиты по бумагам» на
backend. Вручную это же можно сделать так:

```bash
curl -X POST "http://localhost:8085/api/quik-bridge/sovcom" \
  -H "Content-Type: application/json" \
  -d '[{"ticker":"GAZP","quantity":10,"price":135.5}]'
```

### 6.3. Финуслуги (вручную)

У Финуслуг нет отчёта в удобном формате — позиции (облигации, ПИФы) заносятся
в `config.yaml` в секцию `external_holdings`:

```yaml
external_holdings:
  - broker: finuslugi
    ticker: "SU26236RMFS8"
    name: "ОФЗ 26236"
    type: "bond"
    quantity: 50
    current_price: 750.0
    pnl_pct: 1.2
```

## 7. Использование

### 7.1. Через REST API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | статус всех 18 платформ |
| GET | `/api/portfolio` | агрегированный портфель |
| GET | `/api/recommend?deposit=15000` | план покупок на сумму |
| POST | `/api/import-report/{broker_id}` | загрузка отчёта |
| POST | `/api/quik-bridge/{broker_id}` | приём позиций из QUIK |
| GET | `/api/config` | текущий конфиг портфеля |
| POST | `/api/config` | сохранить конфиг |

Пример — получить план на 15 000 ₽:

```bash
curl "http://localhost:8085/api/recommend?deposit=15000"
```

Ответ содержит список `orders` с полями `ticker`, `lots_to_buy`, `shares_count`,
`total_cost`, `target_share_pct` и итоговый `unspent_cash` (остаток).

### 7.2. Через Telegram-бота

Напишите боту команды:

| Команда | Действие |
|---|---|
| `/start` | подсказка |
| `/status` | сводка: ИИС, маржа, TMON |
| `/buy 15000` | план покупок на сумму |
| `/tails` | статус «хвостов» на выход |

Бот также сам присылает сигнал, когда какой-то «хвост» достиг целевого PnL
(проверка каждые 30 минут).

### 7.3. Через настольный клиент / Android

- **Windows**: установите `.msi` / `.exe` из релиза.
- **Linux**: установите `.deb` (Ubuntu/Debian), `.rpm` (Fedora/РЕД ОС/Simply Linux)
  или запустите `.AppImage`.
- **Android**: установите `.apk`.

Клиент подключается к backend по адресу `http://127.0.0.1:8085`. Если backend
запущен на другом компьютере, укажите его адрес в `ApiClient` при запуске.

## 10. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| `/api/health` показывает «не настроен» | не заполнен `TINVEST_TOKEN` в `.env` |
| Брокер «connected = false» | неверный токен, нет сети, или у API тех. сбой |
| Отчёт не импортировался (0 позиций) | парсер не нашёл строку заголовков — проверьте, что в отчёте есть колонки «тикер/код/ISIN» и «количество» |
| В плане не хватает денег на целый лот | остаток остаётся в `unspent_cash` — это нормально, целые лоты |
| Telegram-бот молчит | не заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` |
| `pip install` не находит `t-tech-investments` | SDK Т-Инвестиций публикуется на отдельном индексе T-Bank — добавьте `--extra-index-url https://opensource.tbank.ru/api/v4/projects/238/packages/pypi/simple --trusted-host opensource.tbank.ru` |

## 11. Ограничения альфа-версии

- Парсеры отчётов ориентированы на типовой формат и могут не сработать на
  нестандартных выгрузках конкретного брокера.
- Расчёт цен по отчётам — по данным самого отчёта (могут устаревать).
- Реальный трейдинг и автоматические заявки **не выполняются**.

Сообщайте о проблемах в Issues репозитория:
https://github.com/Chistovik92/invest-advisor/issues
